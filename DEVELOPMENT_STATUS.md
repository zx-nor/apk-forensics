## Milestone 2 scope
- **Identification:** content-based; refined container formats (APK, AAB, JAR, DOCX, XLSX, PPTX, ODF,
  WAV, WebP, MP4, MOV, M4A, HEIC); extension mismatch against the refined format; appended data
  (PNG, JPEG, PDF, WAV); embedded signatures reported as leads only.
- **ZIP:** ZIP64, prepended data, validated end record (fake records in comments rejected), local
  header checks, path checks, symlinks described and never followed, encryption identified but not
  decrypted, bounded measurement of real size and CRC, configurable compression-ratio check, nested
  archives inspected from temporary files that are deleted afterward, shared inspection budget.
- **Metadata:** JPEG, PNG, WebP, TIFF/EXIF (with GPS), PDF Info, OOXML properties, MP3 (ID3v1/v2),
  FLAC, WAV, MP4/MOV, APK manifest and signer certificates, SQLite header. Each result has an
  explicit status: EXTRACTED, NO_METADATA_PRESENT, EXTRACTION_FAILED, or NOT_SUPPORTED.
- **Portability:** the XML reader for OOXML is written in plain Kotlin, because Android does not
  provide `javax.xml.stream`. It resolves only the predefined entities and numeric references; any
  other entity is an error, and a DOCTYPE is reported but never expanded.

## Known limitations
- 7z and RAR: identified by signature only; no listing or extraction.
- Encrypted OOXML (OLE containers) and encrypted archives: not analyzed for content.
- HEIC item metadata, AAB and ODF content, AVI: identified only.
- APK signatures are parsed, not cryptographically verified. Permissions are reported as declared and
  are not used to judge an app.
- XMP parsing covers a subset of common properties.
- MP3 bitrate reflects the first frame only.
- Embedded signature hits are leads, not extracted content.
- Large files are scanned only up to `maxEmbeddedScanBytes` (256 MiB by default).
- The app keeps only one working copy of evidence and does not persist analysis results.
